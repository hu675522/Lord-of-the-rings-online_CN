2026-10-16，针对“商城还是英文”的反馈，已完成工作区原型。本次还原后游戏保持英文，未安装浏览器脚本、未替换客户端程序、未开启调试端口。

之前部署的 DAT 仅把窗口标题改为“LOTRO 商城”，网页本身没有接入翻译，这就是截图仍为英文的原因。**本原型尚未连接真实商城，不能据此称为商城汉化成功。**

## 本轮已实现

1. `store-zh.user.js` 升至 0.2.0，补齐截图中的账号骑术、共享衣橱促销、排序和底部链接等已知文案。支持后续动态加载、输入框提示更新和重复接入保护。未知商品保持英文，商品和说明尚未全量收集。
2. `embedded-bridge.cjs` 只向已确认属于本机游戏进程的回环调试端口连接，仅接入 HTTPS `store.lotro.com` 页面；不记录完整会话 URL、账号、余额或价格。它把同一份文字替换脚本送到内嵌网页，保持游戏内商城窗口。
3. `build_embedded_candidate.py` 针对本机确定的客户端版本生成了独立程序候选 `embedded-candidate/lotroclient64.exe`，文件只保存在工作区，并附有原件／候选 SHA-256、原始和修改字节、位置及可逆性验证记录。

这里的接入候选是对客户端程序的实验性修改，独立于 DAT 资源补丁，现有五文件安装器不会安装它。原型候选不随 GitHub 源码分发。

## 接入候选修改的具体内容

本机 CEF 调试端口默认关闭。候选将 CEF 初始化函数内的一条 10 字节赋值指令，从设置“未捕获 JavaScript 异常栈深度为 20”，改为设置“调试端口为 19222”。异常栈深度回到默认的 0，这会减少脚本异常的堆栈信息。其余字节不变，逆向应用原始字节可恢复完整原件哈希。

只支持客户端 SHA-256：`d131a79b23beaf580221df60c6308e339b72bfb93b39b2817b3d51828a8c39f2`，CEF 版本 `99.2.10+gfecf7ca+chromium-99.0.4844.51`。版本或原始指令不符即停止，不尝试通用扫描修改。

**静态校验通过不等于客户端启动或商城接入通过。** 仍需验证启动器是否覆盖候选、游戏是否启动，以及调试监听是否仅在回环地址；桥接程序遇到非回环监听、非游戏进程、未知域名时拒绝执行翻译。没有连接真实页面前也不能确定网页主域、iframe 和布局全部符合预期。

## 后续测试步骤

本轮不部署。下一轮如安排测试，应将程序候选与 DAT 分开处理：先备份原始客户端程序，核对全部哈希，只测试接入候选，确认能正常启动、监听为回环地址且属于本游戏。通过后再打开商城，运行：

```powershell
node localization/store/embedded-bridge.cjs --game-dir 'D:\Program Files\StandingStoneGames\The Lord of the Rings Online' --port 19222
```

`--once` 可只探测／接入一轮。没有启用调试入口时，程序只报告未接入，不会自动修改游戏或打开端口。

接入后先验证分类标题和截图里的两件骑术商品，再验证切换分类、滚动加载和重新打开。测试不需要购买商品。关闭桥接程序后，当前页已有的翻译可能保留到关闭／重新打开商城；还原程序原件并重启游戏可移除调试入口。

7 项 Node 测试验证词条、动态 DOM、重复接入、价格／输入值／链接和事件保护、域名限制及进程／回环检查。2 项 Python 检查验证版本拒绝和候选修改的边界与可逆性；真实游戏测试仍未完成。
